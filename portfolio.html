담당 범위
ZETIC.ai에서 Android·iOS용 온디바이스 AI 추론 라이브러리, 기기 벤치마킹 시스템과 데모 앱을 개발했습니다. C++ 코어와 Kotlin·Swift 인터페이스, 빌드 구조를 함께 다뤘습니다.
라이브러리
ONNX Runtime·Qualcomm QNN·TFLite SDK를 이용한 추론 기능을 구현했습니다. Android Studio·Xcode에서 사용할 수 있도록 Gradle·CMake 기반 빌드 구조를 설계했습니다.
메모리 관리
Java의 GC와 네이티브 객체의 수명이 다른 환경에서 JNI·Swift 인터페이스를 개발했습니다. 비동기 호출을 포함한 언어 간 객체 생명주기를 맞추고, 래핑 과정의 메모리 사용과 누수를 관리했습니다.
벤치마킹
기기별 모델 런타임 선택에 사용할 측정 시스템을 만들었습니다. Python·boto3로 AWS Device Farm 테스트 패키지를 생성·배포하고, Android·iOS에서 추론 시간과 SNR을 측정했습니다. 결과는 기기·런타임·칩 종류별 보고서로 정리했습니다.
앱 배포
YOLOv8·YAMNet·Face Detection·Whisper·LLaMA 모델용 전후처리를 구현했습니다. Tokenizer·Mel-spectrogram·NMS와 Camera2·오디오 입력을 연결한 데모 앱을 Play Store·App Store에 배포했습니다.

Diggin’ Room

음악 추천 숏폼 서비스

GitHub ↗Play Store ↗
서비스·역할
사용자의 탐색 행동을 바탕으로 음악을 추천하는 숏폼 서비스입니다. 초기 아이디어와 앱 흐름을 기획하고, Android 아키텍처·가중치 기반 추천 알고리즘·영상 플레이어를 구현했습니다. 팀 서비스 사용자 약 60명을 확보했습니다.
영상 재생
처음에는 HLS 직접 스트리밍을 검토했지만, YouTube 음악 데이터를 활용하고 개발 기간을 줄이기 위해 WebView와 IFrame API를 선택했습니다. JavaScript로 로딩·재생·일시정지를 제어하고, 상태를 Kotlin에 전달하도록 인터페이스를 연결했습니다.
페이징
세로 스와이프로 탐색하고 가로 스와이프로 선호하지 않는 음악을 넘기는 동작을 구현했습니다. RoomPager의 페이징 상태에 따라 화면 밖 플레이어를 미리 로딩하고 현재 영상의 재생을 제어했습니다.
의존성 관리
객체 수가 늘어나며 수동 의존 관계 관리가 복잡해졌습니다. Reflection으로 생성자를 탐색해 객체를 주입하는 기능을 만들고, Singleton·Qualifier·Lifecycle 어노테이션과 초기 관계를 표현하는 Kotlin DSL을 지원했습니다.
추천 로직 분리
Spring Service에 들어 있던 추천 알고리즘을 도메인 계층으로 옮겼습니다. Repository를 참조하는 RoomRecommender를 구현하고 백엔드 수정 PR을 작성했습니다. 팀과 구현 내용을 논의한 뒤 반영했습니다.
실행 결과 확인
네트워크 요청과 도메인 로직의 성공·실패를 확인하기 위해 Kotlin Result를 활용한 LogResult를 구현했습니다. 설정한 채널에 따라 콘솔이나 Firebase로 결과를 기록하도록 했습니다.
